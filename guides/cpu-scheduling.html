Comprehensive Guide to CPU Scheduling

Mastering Process Management in Operating Systems

What is CPU Scheduling?

In a multi-programming environment, multiple processes exist in the memory simultaneously. The primary goal of an operating system is to maximize CPU utilization by switching the CPU among processes. This mechanism is called CPU Scheduling.

When the CPU becomes idle, the operating system must select one of the processes in the ready queue to be executed. The selection process is carried out by the short-term scheduler (or CPU scheduler). It picks from among the processes in memory that are ready to execute and allocates the CPU to one of them.

Main Objectives of CPU Scheduling:
  • Maximize CPU utilization (keep the CPU as busy as possible).
  • Maximize Throughput (number of processes completed per unit time).
  • Minimize Waiting Time (total time spent in the ready queue).
  • Minimize Turnaround Time (total time taken to complete a process).
  • Minimize Response Time (time from submission until the first response is produced).

Core Scheduling Metrics

To evaluate the performance of different scheduling algorithms, we use specific metrics:

  • Arrival Time (AT): The time at which the process arrives in the ready queue.
  • Burst Time (BT): The time required by the process for its execution on the CPU.
  • Exit Time (ET): The time at which the process finishes its execution.
  • Turnaround Time (TAT): The total time taken by the process from arrival to completion.
    Formula: TAT = Exit Time - Arrival Time
  • Waiting Time (WT): The total time the process waits in the ready queue before getting the CPU.
    Formula: WT = Turnaround Time - Burst Time

Popular Scheduling Algorithms

1. First Come First Served (FCFS)

As the name suggests, the process that arrives first is executed first. It is a non-preemptive algorithm managed with a FIFO (First-In-First-Out) queue.

Pros: Simple to implement and understand.
Cons: Suffers from the Convoy Effect, where a long process can block many short processes behind it, leading to high average waiting times.

2. Shortest Job First (SJF)

This algorithm picks the process with the smallest burst time. It can be either non-preemptive or preemptive. The preemptive version is called Shortest Remaining Time First (SRTF).

Pros: Provides the minimum average waiting time for a specific set of processes.
Cons: Difficult to implement because it's hard to know the burst time of the next process in advance. Can lead to starvation of longer processes.

3. Priority Scheduling

A priority is associated with each process, and the CPU is allocated to the process with the highest priority (usually the smallest integer represents the highest priority).

Pros: Critical tasks can be prioritized.
Cons: Starvation of low-priority tasks. This is solved by Aging, where the priority of processes waiting in the queue for a long time is gradually increased.

4. Round Robin (RR)

Designed for time-sharing systems, it assigns a small unit of time called a Time Quantum to each process. If the process doesn't finish within its quantum, it is preempted and put back at the end of the ready queue.

Pros: Fair and responsive for interactive users. No process waits forever.
Cons: Performance depends heavily on the size of the time quantum. If too small, context switching overhead increases.

Comparison of Algorithms

Algorithm Type Main Feature Drawback
FCFS Non-Preemptive Simple implementation Convoy Effect
SJF Non-Preemptive Optimal Avg Waiting Time Starvation Possible
Priority Both Supports Task Importance Starvation of Low Priority
Round Robin Preemptive Interactive / Periodic High Context Switch Overhead

Solved Problem: FCFS

Consider 3 Processes:

  • P1: Arrival Time = 0ms, Burst Time = 5ms
  • P2: Arrival Time = 1ms, Burst Time = 3ms
  • P3: Arrival Time = 2ms, Burst Time = 8ms

Step-by-Step Walkthrough:

  1. At Time 0: P1 arrives and starts immediately (CPU idle).
  2. At Time 5: P1 finishes. TAT = 5 - 0 = 5ms. WT = 5 - 5 = 0ms.
  3. At Time 5: P2 (which arrived at 1ms) starts.
  4. At Time 8: P2 finishes. TAT = 8 - 1 = 7ms. WT = 7 - 3 = 4ms.
  5. At Time 8: P3 (which arrived at 2ms) starts.
  6. At Time 16: P3 finishes. TAT = 16 - 2 = 14ms. WT = 14 - 8 = 6ms.

Calculations:

Average TAT = (5 + 7 + 14) / 3 = 8.67ms

Average WT = (0 + 4 + 6) / 3 = 3.33ms
